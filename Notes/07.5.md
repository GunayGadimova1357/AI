## 1. Что такое кросс-валидация

**Кросс-валидация** (или перекрёстная проверка) — это метод оценки качества модели машинного обучения, при котором имеющийся набор данных многократно делится на обучающую и тестовую выборки.

---

## 2. Зачем используется кросс-валидация

Обычно данные делят на две части: обучение (train) и тест (test). Однако у этого подхода есть минусы: если тестовая выборка окажется удачной или, наоборот, очень сложной, оценка модели будет искажена. 

Кросс-валидация решает эти проблемы:
- Максимальное использование данных: Вся доступная информация используется и для обучения, и для тестирования, что крайне важно при небольших размерах датасета.
- Объективная оценка: Модель тестируется на разных частях данных, что дает более точное представление о ее реальной точности.
- Выявление переобучения: Если на одних частях данных модель показывает отличные результаты, а на других — провальные, значит, она переобучилась и "запомнила" обучающий набор

---

## 3. Почему обычного Train/Test разделения иногда недостаточно

Обычного деления данных на обучающую (Train) и тестовую (Test) выборки бывает недостаточно из-за риска утечки данных, переобучения гиперпараметров и высокой дисперсии оценки. Если использовать только два набора, модель может случайно «выучить» структуру именно этого теста, показав ложно завышенную точность.

1. Проблема «подгонки» под тест (Data Leakage): Когда вы настраиваете гиперпараметры модели (например, глубину дерева, learning rate) и ориентируетесь при этом на метрику тестового набора, вы неявно обучаете модель на тесте. Тестовая выборка перестает быть независимой, и оценка модели для реальных задач оказывается завышенной.
2. Зависимость от случайного разбиения: Разбиение 80/20 может быть неудачным. В тестовую выборку могут случайно попасть выбросы или, наоборот, легкие примеры. Оценка модели будет сильно колебаться в зависимости от того, как именно поделились данные (проблема высокой дисперсии).
3. Нехватка данных: Если данных изначально мало, выделение большого куска под тест приведет к тому, что модели не хватит информации для обучения. Если выделить под тест слишком мало, оценка станет ненадежной и случайной.

## 4. Принцип работы K-Fold Cross Validation

**K-Fold Cross Validation** (k-блочная кросс-валидация) — это метод оценки качества модели машинного обучения.

Как работает алгоритм:

1. Разбиение на фолды: Весь ваш датасет случайным образом делится на k равных непересекающихся блоков (folds). Чаще всего выбирают значения k = 5 или k = 10.
2. Обучение и валидация: Процедура повторяется k раз. В каждой итерации один из блоков берется как тестовый (validation) набор, а все остальные k-1 блоков объединяются в обучающий (train) набор.
3. Оценка: Модель обучается на обучающей части и проверяется на тестовой, а затем рассчитывается метрика качества (например, точность Accuracy, R² Score или MSE).
4. Усреднение результатов: После завершения всех k итераций получают k значений метрики. Вычисляется среднее арифметическое значение, чтобы получить финальную и надежную оценку работы модели.

---


## 5. Понятия Train set, Validation set, Test set

В машинном обучении исходный набор данных делят на три части, чтобы модель могла учиться на одних данных, подбирать параметры на других и объективно доказывать свою эффективность на третьих.

### Train set 

**Train set** — это обучающая выборка.

Самая большая часть данных (обычно 60–80% всего датасета).

Используется для непосредственного обучения модели. На этих данных алгоритм находит закономерности и настраивает свои внутренние веса.

---

### Validation set

**Validation set** — это валидационная выборка. 

Промежуточный набор данных (обычно 10–20%).

Применяется для оценки качества модели в процессе обучения. По нему настраивают гиперпараметры (скорость обучения, количество слоев нейросети и т.д.), чтобы улучшить обобщающую способность алгоритма.

Validation set не должен использоваться для финальной оценки качества модели.

---

## Test set

**Test set** — это тестовая выборка.

Финальный набор данных (обычно 10–20%).

Служит для окончательной, непредвзятой проверки модели. Именно этот набор показывает, как алгоритм поведет себя в реальных условиях на новых, не виданных ранее данных.

---


## 6. Как выбирается значение K

Значение K выбирается исходя из компромисса между точностью оценки модели и вычислительными затратами. На практике чаще всего используют K = 5 или K = 10, так как они обеспечивают оптимальный баланс.

При выборе K учитывают следующие факторы:
1. Размер набора данных: Для небольших выборок используют большее K, чтобы не лишать модель обучающих данных (в крайнем случае K равно размеру датасета — метод Leave-One-Out). Для очень больших датасетов, наоборот, достаточно меньшего K (например, 5), чтобы не тратить время на обучение модели сотни раз.
2. Вычислительные ресурсы: Чем больше K, тем больше итераций обучения предстоит сделать. Например, при K = 10 модель обучается 10 раз. Это может быть ресурсозатратно для сложных нейросетей или больших массивов данных.
3. Смещение и дисперсия: Меньшее K (например, 2 или 3) дает более высокую погрешность оценки (смещение), но при этом сама оценка будет более стабильной. Большее K дает более точную, но менее стабильную оценку (так как наборы данных для обучения от фолда к фолду почти не меняются, оценка может сильно варьироваться из-за случайного распределения).

---

## 7. Преимущества кросс-валидации

- Эффективное использование данных: Все наблюдения участвуют как в обучении, так и в тестировании. Это критично при малом объеме обучающей выборки.
- Надежная оценка: Уменьшает зависимость метрик от случайного разделения данных (например, метод K-Fold снижает дисперсию оценки по сравнению с простой отложенной выборкой).
- Защита от переобучения: Помогает подобрать оптимальные гиперпараметры модели, которые будут хорошо работать на реальных, невидимых данных.

---

## 8. Недостатки кросс-валидации

- Высокие вычислительные затраты: Требует многократного обучения и оценки модели, что критично для больших наборов данных или тяжелых нейросетей.
- Увеличение времени работы: В таких методах, как Leave-One-Out, где модель обучается столько раз, сколько объектов в выборке, процесс может стать крайне медленным.
- Нарушение структуры временных рядов: Метод плохо работает с последовательными данными, так как обучение на будущих событиях для прогнозирования прошлого искажает результаты (здесь требуются специальные подходы).

---

## 9. Пример использования в Python (cross_val_score, KFold).

Связка cross_val_score и KFold из библиотеки scikit-learn используется для надежной оценки качества модели. KFold делит данные на K блоков, а cross_val_score обучает и тестирует модель на этих блоках, возвращая оценку для каждого из них.

```python
import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import KFold, cross_val_score

data = load_diabetes()
X, y = data.data, data.target

model = LinearRegression()

# n_splits - количество блоков (фолдов) 
# shuffle - перемешивание данных перед разбиением 
# random_state - для воспроизводимости результатов (фиксирует случайность)
kf = KFold(n_splits=5, shuffle=True, random_state=42)

# model - модель, которую мы хотим проверить
# x - это признаки (данные, по которым модель делает предсказание)
# y - это правильные ответы
# cv принимает объект KFold 
# scoring - метрика качества
scores = cross_val_score(
    model,
    X,
    y,
    cv=kf,
    scoring="r2"
)

print(f"Scores for each fold: {scores}")
print(f"Mean R² score: {np.mean(scores):.3f}")
print(f"Standard deviation: {np.std(scores):.3f}")

```
