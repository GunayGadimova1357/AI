# Кросс-валидация

## 1. Что такое кросс-валидация

**Кросс-валидация** — это метод оценки качества модели машинного обучения, при котором данные несколько раз делятся на обучающую и проверочную части.

Главная идея кросс-валидации в том, чтобы проверить модель не один раз, а несколько раз на разных частях данных.

Это помогает понять, насколько стабильно модель работает и не зависит ли результат от случайного разделения данных.

---

## 2. Зачем используется кросс-валидация

Кросс-валидация используется для того, чтобы:

- более честно оценить качество модели;
- проверить, не переобучилась ли модель;
- сравнить несколько моделей между собой;
- подобрать гиперпараметры модели;
- понять, насколько модель стабильна на разных данных.

Обычное разделение данных может дать случайный результат. Например, если в test set случайно попались слишком лёгкие данные, модель покажет завышенное качество. Если попались слишком сложные данные, качество будет занижено.

Кросс-валидация уменьшает влияние такого случайного разделения.

---

## 3. Почему обычного Train/Test разделения иногда недостаточно

Обычно данные делят так:

```text
Данные → Train set + Test set
````

Например:

```text
80% данных → Train set
20% данных → Test set
```

Модель обучается на train set, а затем проверяется на test set.

Но у такого подхода есть проблемы.

---

### Проблема 1: результат зависит от случайного разбиения

Если данные разделить один раз, итоговая оценка модели может сильно зависеть от того, какие объекты попали в train set, а какие — в test set.

Например, модель может случайно получить лёгкие примеры в test set и показать хороший результат.

Или наоборот — в test set попадут сложные объекты, и модель покажет плохой результат.

---

### Проблема 2: мало данных для обучения

Если данных мало, то выделение отдельной test-части уменьшает количество данных для обучения.

Например, если всего 100 объектов, а 20 отдали на test set, модель обучается только на 80 объектах.

Это может ухудшить качество обучения.

---

### Проблема 3: сложно понять стабильность модели

Один train/test split показывает качество модели только на одном варианте разделения данных.

Но он не показывает, как модель поведёт себя на других частях данных.

Кросс-валидация решает эту проблему, потому что модель проверяется несколько раз.

---

## 4. Понятия Train set, Validation set, Test set

## Train set

**Train set** — это обучающая выборка.

На этих данных модель обучается и подбирает внутренние параметры.

Например, в линейной регрессии модель на train set подбирает коэффициенты.

```text
Train set → используется для обучения модели
```

---

## Validation set

**Validation set** — это проверочная выборка.

Она используется для настройки модели и подбора гиперпараметров.

Например, с помощью validation set можно выбрать:

* глубину дерева решений;
* количество соседей в KNN;
* параметр регуляризации;
* количество деревьев в Random Forest.

```text
Validation set → используется для проверки модели во время настройки
```

Validation set не должен использоваться для финальной оценки качества модели.

---

## Test set

**Test set** — это тестовая выборка.

Она используется только в самом конце, когда модель уже выбрана и настроена.

Test set показывает, как модель будет работать на новых данных.

```text
Test set → используется для финальной оценки модели
```

Важно: test set нельзя использовать для подбора параметров, иначе оценка качества будет нечестной.

---

## 5. Принцип работы K-Fold Cross Validation

**K-Fold Cross Validation** — это один из самых популярных методов кросс-валидации.

Суть метода:

1. Данные делятся на K равных частей.
2. Модель обучается K раз.
3. Каждый раз одна часть используется как validation set.
4. Остальные K-1 частей используются как train set.
5. В конце считается среднее значение метрики.

---

## Пример при K = 5

Допустим, данные делятся на 5 частей:

```text
Fold 1
Fold 2
Fold 3
Fold 4
Fold 5
```

Тогда обучение и проверка будут выглядеть так:

```text
1-я итерация:
Validation → Fold 1
Train      → Fold 2 + Fold 3 + Fold 4 + Fold 5

2-я итерация:
Validation → Fold 2
Train      → Fold 1 + Fold 3 + Fold 4 + Fold 5

3-я итерация:
Validation → Fold 3
Train      → Fold 1 + Fold 2 + Fold 4 + Fold 5

4-я итерация:
Validation → Fold 4
Train      → Fold 1 + Fold 2 + Fold 3 + Fold 5

5-я итерация:
Validation → Fold 5
Train      → Fold 1 + Fold 2 + Fold 3 + Fold 4
```

В итоге каждая часть данных один раз становится validation set.

---

## 6. Как считается итоговый результат

После каждой итерации получается значение метрики.

Например, для 5-Fold Cross Validation:

```text
Fold 1 → accuracy = 0.82
Fold 2 → accuracy = 0.85
Fold 3 → accuracy = 0.80
Fold 4 → accuracy = 0.84
Fold 5 → accuracy = 0.83
```

Итоговая оценка:

$$
Score = \frac{0.82 + 0.85 + 0.80 + 0.84 + 0.83}{5}
$$

$$
Score = 0.828
$$

То есть среднее качество модели равно 0.828.

Также можно смотреть стандартное отклонение. Если разброс между fold-ами большой, значит модель работает нестабильно.

---

## 7. Как выбирается значение K

Значение **K** показывает, на сколько частей делятся данные.

Чаще всего используют:

```text
K = 5
```

или

```text
K = 10
```

---

## K = 5

При K = 5 данные делятся на 5 частей.

Плюсы:

* работает быстрее;
* подходит для больших датасетов;
* даёт достаточно надёжную оценку.

Минусы:

* оценка может быть немного менее точной, чем при K = 10.

---

## K = 10

При K = 10 данные делятся на 10 частей.

Плюсы:

* часто даёт более стабильную оценку;
* модель обучается на большей части данных.

Минусы:

* работает дольше, потому что модель обучается 10 раз.

---

## Как выбрать K

Обычно:

* если данных много, можно использовать K = 5;
* если данных меньше, можно использовать K = 10;
* если модель обучается очень долго, лучше брать меньшее K;
* если нужна более точная оценка, можно брать большее K.

На практике чаще всего используют 5-Fold или 10-Fold Cross Validation.

---

## 8. Преимущества кросс-валидации

Кросс-валидация имеет несколько важных преимуществ.

---

### Более надёжная оценка модели

Модель проверяется не один раз, а несколько раз.

Поэтому итоговая оценка меньше зависит от случайного разделения данных.

---

### Эффективное использование данных

Каждый объект хотя бы один раз используется для проверки и несколько раз используется для обучения.

Это особенно полезно, если данных мало.

---

### Помогает обнаружить переобучение

Если модель показывает очень хорошее качество на train set, но плохое качество на validation set, это может означать переобучение.

Кросс-валидация помогает заметить такую проблему.

---

### Удобна для сравнения моделей

Можно сравнить несколько моделей по среднему результату кросс-валидации.

Например:

```text
Linear Regression → CV Score = 0.72
Random Forest     → CV Score = 0.85
KNN               → CV Score = 0.78
```

В этом случае Random Forest показывает лучший результат.

---

## 9. Недостатки кросс-валидации

Несмотря на плюсы, у кросс-валидации есть и недостатки.

---

### Требует больше времени

Модель обучается не один раз, а K раз.

Если K = 10, модель обучается 10 раз.

Это может быть долго для больших данных или сложных моделей.

---

### Не всегда подходит для временных рядов

Если данные зависят от времени, обычный K-Fold может быть неправильным.

Например, нельзя обучаться на будущих данных и проверяться на прошлых.

Для временных рядов лучше использовать специальные методы, например TimeSeriesSplit.

---

### Нужно правильно выбирать стратегию разделения

Для классификации часто используют StratifiedKFold, чтобы сохранить пропорции классов.

Для обычного KFold классы могут распределиться неравномерно.

---

### Может быть сложнее для новичков

Train/Test split проще понять и использовать.

Кросс-валидация требует понимания fold-ов, validation set и правильной интерпретации результатов.

---

## 10. Пример использования cross_val_score в Python

Ниже пример для задачи регрессии.

```python
from sklearn.datasets import make_regression
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import cross_val_score

# Создаём искусственный датасет для регрессии
X, y = make_regression(
    n_samples=100,
    n_features=3,
    noise=10,
    random_state=42
)

# Создаём модель
model = LinearRegression()

# Выполняем кросс-валидацию
scores = cross_val_score(
    model,
    X,
    y,
    cv=5,
    scoring="r2"
)

print("Результаты на каждом fold:")
print(scores)

print("Средний результат:")
print(scores.mean())
```

---

## Объяснение кода

```python
X, y = make_regression(...)
```

Создаёт искусственные данные для задачи регрессии.

```python
model = LinearRegression()
```

Создаёт модель линейной регрессии.

```python
cross_val_score(model, X, y, cv=5, scoring="r2")
```

Запускает 5-Fold Cross Validation.

Параметр `cv=5` означает, что данные будут разделены на 5 частей.

Параметр `scoring="r2"` означает, что качество модели будет оцениваться с помощью метрики R².

## 11. Пример использования KFold в Python

Если нужно вручную задать способ разделения данных, можно использовать KFold.

```python
from sklearn.datasets import make_regression
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import KFold, cross_val_score

# Создаём данные
X, y = make_regression(
    n_samples=100,
    n_features=3,
    noise=10,
    random_state=42
)

# Создаём модель
model = LinearRegression()

# Создаём объект KFold
kf = KFold(
    n_splits=5,
    shuffle=True,
    random_state=42
)

# Запускаем кросс-валидацию
scores = cross_val_score(
    model,
    X,
    y,
    cv=kf,
    scoring="r2"
)

print("R² на каждом fold:")
print(scores)

print("Средний R²:")
print(scores.mean())

print("Стандартное отклонение:")
print(scores.std())
```

---

## Объяснение KFold

```python
KFold(n_splits=5)
```

Делит данные на 5 частей.

```python
shuffle=True
```

Перемешивает данные перед разделением.

```python
random_state=42
```

Фиксирует случайность, чтобы результат можно было повторить.

```python
cv=kf
```

Передаёт свой способ разделения в cross_val_score.

## 12. Пример с несколькими метриками

Для регрессии можно использовать разные метрики.

```python
from sklearn.datasets import make_regression
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import cross_val_score

X, y = make_regression(
    n_samples=100,
    n_features=3,
    noise=10,
    random_state=42
)

model = LinearRegression()

r2_scores = cross_val_score(
    model,
    X,
    y,
    cv=5,
    scoring="r2"
)

mae_scores = cross_val_score(
    model,
    X,
    y,
    cv=5,
    scoring="neg_mean_absolute_error"
)

mse_scores = cross_val_score(
    model,
    X,
    y,
    cv=5,
    scoring="neg_mean_squared_error"
)

print("Средний R²:", r2_scores.mean())
print("Средний MAE:", -mae_scores.mean())
print("Средний MSE:", -mse_scores.mean())
```

---

## Почему MAE и MSE отрицательные в sklearn

В `sklearn` некоторые метрики ошибок возвращаются со знаком минус.

Например:

```python
scoring="neg_mean_absolute_error"
```

Это связано с тем, что `cross_val_score` считает: чем больше score, тем лучше.

Но для MAE и MSE всё наоборот: чем меньше ошибка, тем лучше.

Поэтому sklearn возвращает отрицательное значение, а для нормальной интерпретации его умножают на `-1`.

Пример:

```python
MAE = -mae_scores.mean()
```
